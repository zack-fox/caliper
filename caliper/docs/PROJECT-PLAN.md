# Caliper 设计与开发规划

本文件是四步闭环、六套规则库与阶段路线的唯一依据；与代码冲突时以本文件为准，修改需同步更新。

## 一、定位

单机离线的等保现场取证与判定工作台。围绕一条链：

```
采集命令库 → 现场材料 → 记录表生成 → 记录表判定 → 风险分析 / 整改建议 → 高风险 / 重大隐患
```

代码只是加载器与执行器，规则库才是资产。基座先稳定，规则靠案例持续迭代。

## 二、第一版边界（已确认）

| 项 | 决定 |
| --- | --- |
| 材料 | 先支持 uniTerm 会话日志（同一文件可含多个采集脚本）；配置、截图、代码片段后置 |
| 资产 | 服务器、数据库、网络/安全设备分开建模；共享测评项，按厂商/平台独立采集适配器与规则 |
| 记录表 | 以公司日常记录表为唯一基准；平台四表降为附带导出 |
| 结果记录 | 按测评指导书实施点逐条生成「经核查：1）…2）…」，每条带证据结论 |
| 符合情况 | 三值带分：符合(1分) / 不符合(0分) / 不适用 |
| 采集 | 应用只生成分区化命令脚本；SSH 直采只预留接口 |
| 整改建议 | 规则给事实、条款与建议骨架，大模型只做语言润色 |
| 云端调用 | 只发结构化结论字段（问题标题、影响、条款号、建议草稿），证据原文不出机 |
| 风险结论 | 系统给候选与依据，人工确认后才进入导出 |

## 三、分层架构

| 层 | 模块 | 职责 |
| --- | --- | --- |
| 证据层 | `core/evidence`、`core/checks` | 装载日志/配置/附件，切分为检查块，登记文件哈希 |
| 记录层 | `core/items`、`core/records` | 记录表模型（公司 9 列口径）与由判定结果构建记录行 |
| 判定层 | `core/rules`、`core/judge` | 规则 DSL、实施点级判定、证据锚点与标准条款 |
| 结论层 | `core/issues`、`core/major`、`core/remediation` | 问题汇总、高风险、重大隐患与整改建议 |
| 规则层 | `packs/<pack>/` | 六套规则库与清单，可整体替换 |
| 呈现层 | `app/` | 桌面外壳与五页工作流，不承载判定逻辑 |

## 四、六库统一框架

`packs/<pack>/library.yaml` 是唯一清单。每个库都必须声明 `title / status / path(s)`，
条目统一字段：`rule_id / 适用等级 / 适用资产类型 / 输入块 / 条件 DSL / 输出字段 / 标准条款 / 判定依据 / 版本`。
`status` 为 `active` 时必须有规则；`scaffold` 表示框架已就位、规则待补。

| key | 库 | 输入 | 输出 |
| --- | --- | --- | --- |
| `capture` | 数据采集命令库 | 资产类型 / OS / 等级 | 分区命令脚本与期望输出格式 |
| `record` | 记录表生成规则库 | 检查块 + 资产信息 | 记录表 9 列字段与结果记录句式 |
| `judge` | 记录表判定规则库 | 检查块 + 规则 | 三值结论、实施点、锚点、条款 |
| `remediation` | 风险分析整改库 | 判定结果 | 问题描述、成因、整改动作、优先级 |
| `high_risk` | 高风险判定库 | 判定结果 + 高风险指引 | 是否高风险、能否降风险及前提 |
| `major` | 重大风险隐患库 | 高风险命中 + 相关性/严重性/高发性 | 是否重大隐患及理由 |

依赖方向单向向下，禁止下层规则反向引用上层结论。采集脚本的输出格式必须能被证据层原样解析，形成闭环。

## 五、记录表口径

每个资产一个 sheet，列序固定：

```
序号 | 控制点 | 控制项 | 结果记录 | 符合情况 | 备注 | 重要程度 | 检查内容 | 判断标准
```

表头区记录项目编号、系统名称、核查对象、IP 地址、资产类别、核查时间、测评作业指导书、安全层面。
`结果记录` 以「经核查：」起句，按实施点编号逐条陈述；`符合情况` 只取三值；
`备注` 仅放不适用理由、替代措施与特殊说明，不重复结果记录。

## 六、阶段路线

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| 0 基座 | 资产类型 server/db、记录表模型、六库清单与加载器、回归入口 | `make check` 全绿，六库均可装载 |
| 1 取证补全 | 中间件块映射、采集脚本生成器（对齐 uniTerm 格式） | 现场执行回传的日志 100% 解析 |
| 2 记录表 | 公司格式写入器与逐条文案生成 | 与历史样例逐格比对，差异可解释 |
| 3 判定 | 实施点级判定、分值、锚点与条款 | 可映射检查块全部有结论，未覆盖项显式标注 |
| 4 风险 | 整改建议、高风险降风险、重大隐患三维评分 | 候选结论 + 人工确认留痕，可导出 |
| 5 规则填充 | 按脱敏案例批量补六库 | 回归集全绿，规则变更可追溯 |

## 七、最终成果

1. 桌面应用：四步闭环、单机离线、证据不出机，macOS 优先、Windows 可打包
2. 六套规则库：带版本校验与回归案例，可整体替换
3. 四类产物：公司格式记录表、平台四表、问题分析与整改建议、高风险/重大隐患结论
4. 脱敏案例回归库与三份文档：证据格式规范、规则库编写指南、验收标准

## 八、红线与约束

- 仓库不出现真实系统名、项目编号、公网 IP、账号；`案例模版/` 仅本地使用，不入库
- 云端润色只接收结构化字段，发送前必须预览；原始日志与证据片段不出机
- 每条结论必须带证据锚点、规则版本与标准条款；规则或证据变化后，人工确认自动失效
- 规则库缺失、版本不符或引用不存在的检查块时，运行必须失败而不是静默跳过

## 九、当前基线

以本地一份 uniTerm 会话日志实测：可提取 53 个检查块，其中 44 个命中现有检查映射；
未命中的 9 类集中在 NGINX / Apache / Tomcat / Docker / 数据库等中间件分区。
同一文件内可串接多个采集脚本，分区编号会重复，解析按脚本边界分段处理。
